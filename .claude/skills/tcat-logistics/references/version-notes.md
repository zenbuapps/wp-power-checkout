## 2. v1.9.3 → v2.0.0 逐項變更

### 2.1 新增

**① 新欄位 `IsMobilePay`（是否允許手機支付）**

| 端點 | 項次 | 型態 | 必要 |
|---|---|---|---|
| `PrintOBT` | 29 | String (1) | N |
| `PrintOBTByPickingList` | 28 | String (1) | N |

值為 `Y`／`N`。位置緊接在 `IsSwipe`（是否允許刷卡）之後。**`PrintOBTByB2S` 與逆物流無此欄位。**

**② 新增附錄二 — 收寄件人姓名允許符號（29 個）**

v1.9.3 只有一個附錄（貨態代碼表）；v2.0.0 拆成「附錄一-貨態代碼表」+「**附錄二-收寄件人姓名允許符號**」。29 個符號完整清單見 `api-reference.md` §13.9。

**③ 姓名 / 電話欄位新增限制敘述**

v2.0.0 在 `RecipientName` / `RecipientTel` / `RecipientMobile` 加上：

- **「（黏貼聯遮蔽）」** — 共出現 6 處（`PrintOBT` 3 處、`PrintOBTByPickingList` 3 處）。表示這些個資會在黏貼聯上遮蔽顯示。**v1.9.3 完全沒有這個註記（0 處）。**
- **「限填入中文（不含生僻字）、英文、數字及部分常用符號（P58_附錄二）」** — 「生僻字」一詞在 v2.0.0 出現 8 處，**v1.9.3 為 0 處**。

> 這是 v2.0.0 最實質的行為變更之一：**姓名欄位的字元集被明確限縮並文件化**。舊系統若曾送過含生僻字或非允許符號的姓名，升級後可能開始被擋。

## 3. ★ 被移除的 8 條貨態代碼：該怎麼處理

**兩份獨立文件在同一波改版中砍掉了完全對應的 8 條代碼**：

| API 附錄（二代）| FTP `.sod`（一代）| 狀態說明 |
|---|---|---|
| `181` | `00004` | 送錯 BASE |
| `182` | `00005` | 送錯 CENTER |
| `241` | `00021` | 超大 |
| `242` | `00022` | 超重 |
| `243` | `00007` | 損壞 |
| `244` | `00014` | 遺失 |
| `245` | `00302` | 客樂得損毀 |
| `246` | `00303` | 客樂得遺失 |

- API 規格書：v1.9.3（39 條）→ v2.0.0（31 條）
- FTP 回檔格式：2021-10-26（40 條）→ 2023-08-22（32 條）

**共同特徵**：全部是「調查處理中」類的貨故 / 異常狀態。

**官方未給任何停用聲明。** 可能是 (a) 這些狀態已停止產生；(b) 改為內部使用不對外回傳；(c) 只是文件精簡。

> **實作結論：仍視為可能出現。** 保留這 8 條的映射（見 `cargo-status.md` §6），並且**必須有 `UNKNOWN` fallback**——官方代碼表已被證實非窮舉（`.sod` 範例檔存在文件未列的 `00000 訂單處理中`）。

## 4. 授權碼（`CustomerToken`）取得流程

來源：《統一速達契約客戶印單API授權碼取得方式說明》

1. 前往速達官網的**契客專區**：`https://www.takkyubin.com.tw/YMTContract/aspx/Login.aspx`
2. 點選「**取得印單 API 授權碼**」進入申請授權碼畫面
3. **選擇要取得的授權碼環境**：
   - **正式站台**：一般作為上線的服務使用
   - **測試站台**：一般作為系統開發測試使用
4. 填入**契客代號**，點選「查詢」
5. 選擇取得授權碼的方式，點選「**發送授權碼**」
6. 確認是否成功取得授權碼

> ⚠️ **若沒有設定聯繫方式**：需下載「**資料變更同意書**」聯繫簽約站所進行資料變更，之後才能使用上述方式取得授權碼。

**實務要點**：

- **正式與測試是兩組不同的授權碼**，環境設定必須成對切換（`TCAT_BASE_URL` + `TCAT_CUSTOMER_TOKEN` 一起換），**不可只換 URL**。
- 授權碼是**自助發送**取得的，不是簽約時一次性給定——**官方未說明有效期限或是否會輪替**。若整合後突然全面 401 / 失敗，先確認授權碼是否需重新發送。
- `CustomerToken` 為 `String(50)`；`CustomerId` 為 10 碼或 12 碼。

## 7. FTP 帳號申請重點（《速達FTP帳號申請表》）

申請表必填欄位（星號為必填）：

- **契客名稱 / 客代**、**契客聯絡電話**
- **連線方式**：FTP／FTPS／SFTP 三擇一
- 契客連線主機 IP —「個資安全建議提供固定連線的 IP 位址，**連線 IP 建議 5 組以內**」
- **聯絡窗口 1**（姓名 / 分機 / e-mail）為必填；窗口 2、3 選填
  - e-mail 用途：**eod 訂單異常時發通知**
- **申請 FTP 用途**（複選，每項可選 **Big5 或 UTF-8** 編碼）：
  - 上拋訂單給黑貓（`.eod`）
  - 需要黑貓貨態回覆檔（`.sod`）
  - 需要黑貓未集貨原因檔（`.nod`）
  - 需要客樂得回檔（`.nom` / `.adj` / `.ret`）
- 預計測試日期（起訖 + 共測試幾日）、預計上線日期

**FTP 開通完成時由統一速達提供**：FTP 帳號、FTP 密碼。

> **編碼在申請時就決定**（Big5 或 UTF-8，且各檔種可分別指定）。程式端**不要寫死**，用設定值控制——見 `ftp-file-formats.md`。
