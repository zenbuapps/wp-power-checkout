# FTP 資料交換與回檔格式（eod / sod / nod / nom / adj / ret）

印單 API 之外的第二條整合路徑：**FTP 檔案交換**。上拋電子訂單（`.eod`）、下載貨態與帳務回檔（`.sod` / `.nod` / `.nom` / `.adj` / `.ret`）。

> ⚠️ **這些全部是「`|` 分隔的變動長度文字檔」，不是定長欄位檔。** 官方原文用全形直線「`│`」描述分隔符，但**實際檔案使用的是 ASCII 半形 `|`（0x7C）**。不要照文件的全形字元去 split。

---

## 1. FTP 連線規格

| 項目 | 內容 |
|---|---|
| FTP Server IP | `103.234.81.11` |
| 支援連線方式 | **FTP**（無加密）／**FTPS 隱式 Implicit**（有加密）／**SFTP**（有加密）|
| 傳輸模式 | **一律 PASV（被動模式）** |
| FTP 帳號 / 密碼 | 開通完成時由統一速達提供（需填「速達FTP帳號申請表」）|
| IP 鎖定 | **僅有開通白名單的 IP 才可登入**。個資安全建議提供固定 IP，**建議 5 組以內** |
| 編碼 | 申請時擇一：**Big5** 或 **UTF-8**（`.eod` 上傳與 `.sod` / `.nod` 下載各自可選）|

### 1.1 防火牆需開通的 Port

| 連線方式 | 需開通 Port |
|---|---|
| FTP | `20`、`21`、`50000~50500` |
| FTPS（隱式 Implicit）| `20`、`21`、**`990`**、`50000~50500` |
| SFTP | `20`、`21`、**`22`**、`50000~50500` |

> **PASV 高位埠區間 `50000~50500` 是最常被忽略的一項**——只開 21/22 會在 LIST / RETR 時卡住。

### 1.2 目錄結構

登入後直接落在該 FTP 帳號對應目錄，底下有五個資料夾：

| 目錄 | 用途 | 保留策略 |
|---|---|---|
| `SEND` | **契客上傳**電子訂單（`.eod`）。速達在每小時的 **05、15、25、35、45、55 分**轉入訂單，轉入後檔案會從此目錄移走 | 轉入即移除 |
| `SENDBK` | 進入速達內部營運系統後的 EOD 備份 | **僅備份 1 天** |
| `RECEIVE` | **契客下載**貨態回檔（`.sod` 等），由速達貨態平台依排程產出 | — |
| `RECEIVEBK` | SOD 回檔備份 | **保留 2 週** |
| `COMMOM` | 其他特殊用途（原文即拼作 `COMMOM`）| — |

> **舊版文件（2004）描述目錄為 `\廠商代號\Send\` 與 `\廠商代號\Receive\`，且 Receive 保留 14 天。** 現行（2023-08-22）版本為登入即進入帳號目錄、五個資料夾、RECEIVEBK 保留兩週。以新版為準。

### 1.3 檔名「後蓋前」陷阱

> 客戶上傳的 `.eod` 檔，**序號由客戶自行控制**。每次上傳的檔名序號**必須都不同**；若上傳相同檔名，會「**後蓋前**」，先前檔案資料**直接遺失且不備份**。

實作上必須確保序號單調遞增（或含時間戳），且**不可 retry 時重用同一檔名**。

## 2. `.eod` — 電子訂單上拋檔（30 欄位）

**目錄**：`SEND`　**檔名**：`XXXMMDDNN.eod`（`XXX`＝FTP 客代／`MMDD`＝月日／`NN`＝序號）
**文件編號**：20230822 編修（二代-電子訂單檔）

| # | 欄位名稱 | 資料型態 | 欄位說明 |
|---|---|---|---|
| 1 | 託運類別 | VARCHAR2(1) | `1`：客戶自行列印託運單／`2`：速達協助列印（由速達系統分配託運單號）／`3`：已有單號，由速達列印（A4 二模）– 逆物流收退貨 |
| 2 | 託運單號 | VARCHAR2(12) | **若上欄為 `2` 時，則此欄空白** |
| 3 | 訂單編號(客戶端) | VARCHAR2(35) | 契約客戶端之訂單編號，**非必填** |
| 4 | 契客代號 | VARCHAR2(10) | 簽約後，速達建完主檔提供之「契約客戶」代號 |
| 5 | 溫層 | VARCHAR2(4) | `0001` 常溫／`0002` 冷藏／`0003` 冷凍（default `0001`）|
| 6 | 距離 | VARCHAR2(2) | `00` 同縣市／`01` 外縣市／`02` 離島（default `00`）|
| 7 | 規格 | VARCHAR2(4) | `0001` 60cm／`0002` 90cm／`0003` 120cm／`0004` 150cm（default `0001`）|
| 8 | 是否代收貨款 | VARCHAR2(1) | `N` 否／`Y` 是（default `N`）|
| 9 | 代收金額 | NUMBER(13) | 若上一欄為 `Y`，則為代收金額（例：100 元 → 值為 `100`）；若為 `N`，此欄固定帶 `0` |
| 10 | 是否到付 | VARCHAR2(1) | **無作用，請固定填 `N`** |
| 11 | 是否付現 | VARCHAR2(2) | `00` 付現／`01` 月結（default `01`）|
| 12 | 收件人姓名 | VARCHAR2(30) | **必須輸入** |
| 13 | 收件人電話 | VARCHAR2(20) | |
| 14 | 收件人手機 | VARCHAR2(20) | **必須輸入** |
| 15 | 收件人郵碼 | VARCHAR2(6) | **必須輸入**，速達前配送地址的六碼郵號 |
| 16 | 收件人地址 | VARCHAR2(120) | **必須輸入** |
| 17 | 寄件人姓名 | VARCHAR2(30) | **必須輸入** |
| 18 | 寄件人電話 | VARCHAR2(20) | 必須輸入，寄件人電話及手機可擇一輸入 |
| 19 | 寄件人手機 | VARCHAR2(20) | 必須輸入，寄件人電話及手機可擇一輸入 |
| 20 | 寄件人郵碼 | VARCHAR2(6) | **必須輸入**，速達前往集貨地址的六碼郵號 |
| 21 | 寄件人地址 | VARCHAR2(120) | **必須輸入**，速達前往集貨地址 |
| 22 | 契客出貨日期／速達印託運單日期 | VARCHAR2(14) | `YYYYMMDDhhmmss` 或系統日期。**ss 秒數若無，用 `00` 補齊 14 位；或只提供到 `YYYYMMDD` 即可** |
| 23 | 希望取件時段 | VARCHAR2(1) | `1`：13 時前／`2`：14~18 時／`4`：不指定（**固定填 `4` 不指定**）|
| 24 | 希望配達時段 | VARCHAR2(1) | `1`：13 時前／`2`：14~18 時／`4`：不指定 |
| 25 | 會員編號 | VARCHAR2(30) | 可選擇性填入 |
| 26 | 物品名稱 | VARCHAR2(60) | 可選擇性填入 |
| 27 | 易碎物品 | VARCHAR2(1) | `N` 否／`Y` 是（default `N`）。**目前無作用：固定填 `N`** |
| 28 | 精密儀器 | VARCHAR2(1) | `N` 否／`Y` 是（default `N`）。**目前無作用：固定填 `N`** |
| 29 | 備註 | VARCHAR2(100) | 可選擇性填入 |
| 30 | SD 路線代碼 | VARCHAR2(9) | 不必填 |

**欄位規則**：
- 編碼為 **Big5 或 UTF-8**（申請時擇一）。
- **欄位實際資料長度不足時，不需補 `0` 或空白**（← 明確不是定長格式）。
- 每個 column 結束以 `|` 區隔，內容為變動長度。

> ⚠️ **`.eod` 的代碼值與印單 API 不同！** 時段代碼 EOD 用 **1 碼**（`1`/`2`/`4`），印單 API 用 **2 碼**（`01`/`02`/`04`）。溫層 / 規格則兩者相同（4 碼）。EOD 另有 API 沒有的「距離」「是否付現」欄位。**兩條路徑不可共用同一組 DTO。**

## 3. `.sod` — 包裹配送狀態回覆檔（貨態）

**目錄**：`RECEIVE`　**檔名**：`XXX MMDD HH.sod`（`XXX`＝客戶 FTP_ID 或客代／`MMDD`＝月日／`HH`＝回檔產檔的時點）
**功能概述**：速達包裹配送狀態回覆檔（契客專用）

| # | Description | Type | Comments |
|---|---|---|---|
| 1 | 託運單號 | VARCHAR2(12) | |
| 2 | 客戶端訂單編號 | VARCHAR2(35) | *(2021 版標 VARCHAR2(20)，2023 版改為 35，與印單 API `OrderId` 一致)* |
| 3 | 營業所名稱 | VARCHAR2(30) | |
| 4 | 貨態輸入日期 | VARCHAR2(14) | `YYYYMMDDhhmmss` |
| 5 | 客戶代號 | VARCHAR2(10) | |
| 6 | 狀態_ID | VARCHAR2(5) | **一代貨態代碼**，見 `cargo-status.md` §4 |
| 7 | 狀態說明 | VARCHAR2(60) | |
| 8 | 規格 | VARCHAR2(3) | **預設不回覆**，客戶可視必要性向簽約站所提出申請。回覆代碼：`01`、`02`、`03`、`04`；對應尺寸：60、90、120、150 |

### 3.1 回檔排程

| 產檔時點 | 涵蓋範圍 |
|---|---|
| **每日 05:00** | 回傳**前一天 18:00 後到隔天 05:00** 的所有狀態 |
| **每日 18:00** | 回傳**當日 05:00 至 18:00** 之間的所有狀態 |

> **SOD 貨態僅供貨物追蹤（查詢）使用。**

### 3.2 真實範例逐行拆解

官方範例檔 `04.一般電子檔-回檔格式-範例檔.sod`（Big5，6 筆）：

```
9811710223| |南港二　所|20040812193853|2082839303|00001|轉運中|
9811710234| |南港二　所|20040812193853|2082839303|00001|轉運中|
9811710201| |士林營業所|20040812200135|2082839303|00003|配完|
9811710212| |斗南營業所|20040812192141|2082839309|00003|配完|
9811710302|01621827||20040813|2082839312|00000|訂單處理中|
9811710313|01622316||20040813|2082839303|00000|訂單處理中|
```

第 1 行拆解：

| 欄位 | 值 | 說明 |
|---|---|---|
| 1 託運單號 | `9811710223` | **僅 10 碼**（此為 2004 年舊樣本；現行為 12 碼）|
| 2 客戶端訂單編號 | `" "`（單一半形空格）| **不是空字串**，是一個空格 |
| 3 營業所名稱 | `南港二　所` | **含全形空白 U+3000** |
| 4 貨態輸入日期 | `20040812193853` | 14 碼 |
| 5 客戶代號 | `2082839303` | |
| 6 狀態_ID | `00001` | 一代代碼 |
| 7 狀態說明 | `轉運中` | |
| 8 規格 | **不存在** | 第 7 欄後直接是行尾的 `\|`，**第 8 欄整欄缺席** |

### 3.3 ★ 解析陷阱（實測歸納）

1. **欄位數會變動**：規格（第 8 欄）預設不回覆時，**整欄不存在**（不是空字串佔位）。parser 必須容忍 7 或 8 欄。
2. **行尾有一個 trailing `|`**：`split('|')` 後最後會多一個空字串，要丟掉。
3. **第 5 行第 4 欄只有 8 碼**（`20040813`）而非 14 碼——**日期長度不保證**，`YYYYMMDDhhmmss` 與 `YYYYMMDD` 混用。
4. **`00000 訂單處理中` 不在任何版本的代碼表中**，但確實出現在官方範例檔。**代碼表非窮舉。**
5. **值可能是空白而非空字串**（第 2 欄的 `" "`），比對前要 `trim()`。
6. **含全形空白**（第 3 欄），顯示與比對時需留意。
7. **最後一行可能沒有換行符**（實測 `.nom` / `.adj` / `.ret` 皆是），不可依賴 `\n` 結尾切行。

```typescript
// 建議 parser
function parsePipeFile(raw: string): string[][] {
  return raw
    .split(/\r?\n/)
    .filter(l => l.trim() !== '')          // 濾掉空行 & 可能缺失的結尾換行
    .map(l => {
      const cols = l.split('|');
      if (cols.at(-1) === '') cols.pop();  // 丟掉行尾 trailing | 造成的空元素
      return cols;                          // ★ 不要 trim 掉整體，個別欄位再 trim
    });
}
```

## 4. `.nod` — 未集貨原因記錄檔（8 欄位）

**目錄**：`RECEIVE`　**檔名**：`XXX MMDDHH.nod`（`XXX`＝客戶 ID／`MMDD`＝月日／`HH`＝序號）
**Table 名稱**：`NOD`（`Oreder_status`，原文即有此拼字）　**文件編號**：201703

| # | Description | Type | Comments |
|---|---|---|---|
| 1 | 託運單號 | VARCHAR2(10) | |
| 2 | 客戶端訂單編號 | VARCHAR2(20) | |
| 3 | 處理單位 | VARCHAR2(20) | |
| 4 | 處理時間 | VARCHAR2(14) | `YYYMMDDhhmmss`（原文即少一個 Y，實際為 14 碼 `YYYYMMDDhhmmss`）|
| 5 | 客戶代號 | VARCHAR2(10) | |
| 6 | 原因代號 | VARCHAR2(05) | **未集貨原因代碼**，14 條見 `cargo-status.md` §7 |
| 7 | 未集貨原因 | VARCHAR2(40) | |
| 8 | 備註 | VARCHAR2(50) | |

**回檔頻率**：傳前一天的所有最新狀態。

### 4.1 真實範例

```
9536283442|20140905001911332001|大雅營業所|20140914152552|7076259101|P26|另約時間 (PP)||
9536283453|20140829001903392001|南門衛星所|20140914170454|7076259101|P26|另約時間 (PP)||
9536283464|20140831002111242001|頭份衛星所|20140914174602|7076259101|P27|電聯不上 (PP)||
9536283475|20140908003012302001|迪化衛星所|20140914092319|7076259101|P26|另約時間 (PP)||
9536283486|20140905003247372001|西屯一營業所|20140914154657|7076259101|P27|電聯不上 (PP)||
```

第 1 行：託運單號 `9536283442`／訂單編號 `20140905001911332001`／處理單位 `大雅營業所`／處理時間 `20140914152552`／客戶代號 `7076259101`／原因代號 `P26`／未集貨原因 `另約時間 (PP)`／備註 **空**。

> 行尾為 `||` — 第 8 欄（備註）是空字串，加上 trailing `|`。**8 欄全在，與 `.sod` 的「整欄缺席」行為不同。**
> **原因代號含英文字母**（`P26`），不可用整數型別。
> **`未集貨原因` 內含半形空格**（`另約時間 (PP)`），不要當成分隔符。

## 5. 客樂得代收貨款回檔（`.nom` / `.adj` / `.ret`）

「客樂得」是黑貓的**代收貨款（COD）帳務服務**。三個檔案於**每週結帳次一日早上 6 點**產生在 FTP。

| 副檔名 | 中文 | 內容 | 是否計入匯款 |
|---|---|---|---|
| `.NOM` | 結帳檔 | 列出結帳週期區間**配送完成 ＆ 退貨**的代收包裹明細 | ✅ **此檔為當次匯款金額之一** |
| `.ADJ` | 調帳檔 | 列出結帳週期區間內**調帳**的代收包裹單號 | ✅ **此檔為當次匯款金額之一** |
| `.RET` | 退貨貨故檔 | 列出結帳週期區間內**退貨 & 貨故**的代收包裹單號，為退貨單號之整理 | ❌ 僅為整理 |

> ⚠️ **「退貨單號會重複出現在 NOM 與 RET 檔裡」**（官方明載）。對帳時**不可把 NOM + RET 直接相加**，會重複計算。**匯款金額 = NOM + ADJ**，RET 只用來標記哪些單號是退貨。

### 5.1 `.nom` — 代收貨款集貨（結帳檔，6 欄位）

**檔名**：`XXX YYMMDD.NOM`（`XXX`＝客戶 FTP 代號／`YYMMDD`＝西元年末 2 碼 + 月月日日）

| # | 欄位名稱 | Type | 備註 |
|---|---|---|---|
| 1 | 寄件日期 | VARCHAR2(8) | `yyyymmdd` |
| 2 | 託運單號 | VARCHAR2(10) | |
| 3 | 訂單編號 | VARCHAR2(20) | |
| 4 | 代收金額(元) | Varchar2(11) | |
| 5 | 手續費(元) | VARCHAR2(11) | |
| 6 | 運費(元) | VARCHAR2(11) | **僅供參考** |

**真實範例**（`XXX070703.nom`）：

```
20080625|9876543210|123456|3000|60|71|
20080625|9876545321|123451|0|30|71|
20080626|9876545320|123457|2000|30|71|
```

第 1 行：寄件日期 `20080625`／託運單號 `9876543210`／訂單編號 `123456`／代收金額 `3000`／手續費 `60`／運費 `71`。

> **第 2 行代收金額為 `0` 但仍收手續費 `30`** — 這是退貨的典型樣態（貨退了、代收沒收到、手續費照算）。對帳邏輯要能處理代收 0 元的列。
> **金額為字串型態（VARCHAR2(11)）、單位為元、無小數點、無千分位。**

### 5.3 `.ret` — 退貨（**7 欄位**）

**檔名**：`XXX YYMMDD.RET`

| # | Description | Type | Comments |
|---|---|---|---|
| 1 | 寄件日期 | VARCHAR2(8) | `yyyymmdd` |
| 2 | **原始單號** | VARCHAR2(10) | ★ RET 專屬：原始去程的託運單號 |
| 3 | 訂單編號 | VARCHAR2(20) | |
| 4 | **託運單號** | VARCHAR2(10) | ★ 退貨這一趟的新單號 |
| 5 | 代收金額(元) | Varchar2(11) | |
| 6 | 手續費(元) | VARCHAR2(11) | |
| 7 | 運費(元) | VARCHAR2(11) | **僅供參考** |

**真實範例**（`XXX070703.ret`，單筆、無結尾換行）：

```
20080624|9876545321|123451|5012345890|0|0|71|
```

拆解：寄件日期 `20080624`／**原始單號 `9876545321`**／訂單編號 `123451`／**託運單號 `5012345890`**／代收金額 `0`／手續費 `0`／運費 `71`。

> ⚠️ **`.ret` 比 `.nom` / `.adj` 多一欄，且第 2、4 欄都是單號**。若三個檔共用同一個 parser，**欄位位移會錯開**：`.ret` 的第 4 欄是單號、而 `.nom` 的第 4 欄是代收金額。**務必按副檔名分派不同 schema。**
> 對照 §5.1 的 `.nom` 範例，`9876545321` / 訂單 `123451` / 代收 `0` / 手續費 `30` 那筆同時出現在 NOM 與 RET——正是官方所說的「退貨單號會重覆出現」。注意兩檔的手續費值不同（NOM `30` vs RET `0`），**以 NOM 為匯款計算依據**。

## 7. 整合檢核清單

- [ ] 分隔符用 **半形 `|`**，不是文件裡的全形 `│`。
- [ ] 行尾有 trailing `|`，split 後要丟掉最後的空元素。
- [ ] **最後一行可能沒有換行符**，切行後要過濾空行。
- [ ] `.sod` 欄位數可能是 **7 或 8**（規格欄預設不回覆時整欄缺席）。
- [ ] 日期欄位長度可能是 **14 或 8**，不可硬性 `substring(0,14)`。
- [ ] 欄位值可能是**空白字元**而非空字串，比對前 `trim()`。
- [ ] 資料可能含**全形空白 U+3000**（營業所名稱）。
- [ ] 一代貨態代碼、NOD 原因代碼**含英文字母且有前導零**，一律當字串。
- [ ] `.eod` 上傳檔名序號**必須唯一**，重複會「後蓋前」且不備份。
- [ ] `.eod` 的時段代碼是 **1 碼**（`1`/`2`/`4`），與印單 API 的 **2 碼**（`01`/`02`/`04`）不同。
- [ ] `.eod` 第 10 欄「是否到付」**無作用固定填 `N`**；第 27、28 欄（易碎 / 精密）**無作用固定填 `N`**；第 23 欄「希望取件時段」**固定填 `4`**。
- [ ] 客樂得對帳：**匯款金額 = NOM + ADJ**，RET 不可相加（退貨單號在 NOM 與 RET 重複出現）。
- [ ] `.ret` 有 7 欄且第 2/4 欄都是單號，**不可與 `.nom` / `.adj` 共用 parser**。
- [ ] 編碼在申請時擇一（Big5 / UTF-8），**程式端不要寫死**，用設定值控制；Big5 解碼在 Node 需 `iconv-lite`（Node 內建不支援 Big5）。
- [ ] PASV 高位埠 `50000~50500` 必須在防火牆開通。
