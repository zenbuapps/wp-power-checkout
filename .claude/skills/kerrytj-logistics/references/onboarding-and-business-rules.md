## 1. 申請開通流程

嘉里大榮**沒有公開的開發者入口 / 自助申請頁**。綜合鼎新 A1 手冊（第三方 ERP 廠商）與官網：

1. **先成為契約客戶**：官網「欲加入嘉里大榮物流契約客戶請洽詢當地服務營業所」；代收貨款、到付、月結都僅限契約客戶（官方營運）。
2. **向所屬營業所（站所）申請開通 API**（鼎新 A1）：
   - 提供**客戶編號**，說明「已完成 API 串接功能、要求開通 API 帳號」。
   - 說明**溫層**（常溫 / 低溫）。
   - 提出**一年所需的託運單號數量**（可先以月用量估全年，或請站所協助估算；大榮通常會多給，不夠可再申請）。
   - 若出貨地分屬**不同營業所**，需分別申請；可註明共用同一組 API 帳密，但**各站單號區間分開使用**。
3. **大榮回覆《客戶 API 串接規格書》**，第 2 頁「API 帳號詳細資訊」表填好**正式 / 測試**兩欄：客戶編號、帳號、密碼、常溫區間起、常溫區間迄（官方規格 v1.1.0）。鼎新 A1 描述的回信內容（客編 / 帳號 / 密碼 / 一年號段）與此一致。
4. 官網「契約會員專區」（`https://www.kerrytj.com/zh/contractmember`，帳號 = 契約會員編號）是**網頁版**服務（帳務查詢、簽收影像下載等），與 API 帳密是兩套；已是路線契約客戶可在 `https://www.kerrytj.com/zh/register` 線上申請網站服務帳號（官方）。
5. 舊式做法：大榮人員到場安裝「KTJ 託運軟體」桌機版 + FTP 傳送託運資料；第三方部落格指出 2023/5/5 起改為網頁版線上 EDI 系統（第三方，非 API）。

### 1.1 測試環境：有

| 項目 | 內容 | 來源 |
|---|---|---|
| 測試主機 | **`https://api.kerrytj.com/EDIEntranceTest/`**（每支 API 規格書都列「正式 URL / 測試 URL」） | 官方規格 |
| 可測端點 | `ShipmentDelivery`、`UpdateShipmentDelivery`、`PickupV2`、`Report/GetLabelPdf`、`Report/GetLabelPdfA4`、`Report/GetDetailPdf` | 官方規格 |
| 存在性 | 2026-10-29 無憑證探測：Help Page 200、36 支端點與正式機相同、建單類 401（Basic realm="api.kerrytj.com"） | 官方實測 |
| 測試帳密 | **與正式帳密分開**（帳號表「測試」欄），含測試客編與測試常溫號段 | 官方規格 |

## 2. 會拿到的憑證與設定值

每個環境（正式 / 測試）各一套：

| 設定值 | 用途 | 來源 |

## 3. 託運單號（BLN）號段管理

**核心事實：託運單號由客戶端配發，不是大榮回傳。** 大榮事先核發一段號碼，客戶系統依序取號帶入 `BLN` 上傳。

| 規則 | 內容 | 來源 |
|---|---|---|
| **常溫** | **11 碼，流水號 +1**（例：`89000000000` → 下一號 `89000000001`），**無檢查碼**；**每一年可重複使用** | 官方規格 |
| **低溫** | **10 碼 = 9 碼貨號 + 1 碼檢查碼**；**檢查碼 = 前 9 碼 ÷ 7 的餘數**（例：`667000000` ÷ 7 = 95285714 餘 **2** → `6670000002`）；**不可重複使用**，快用完請向 KTJ 申請 | 官方規格（規格書範例單號 `6343634496`、`6876384093`、`6088958363` 皆驗算通過） |
| 長度驗證 | Help Page：`BLN` Min 10 / Max 11；貨況 API 常溫固定 11、低溫固定 10 | 官方 schema + 官方規格 |
| 常溫重複使用建議 | 雖可每年重用，仍建議申請新號以保留紀錄、降低查詢混淆 | 鼎新 A1 |
| 多物流設定拆號段 | 同一出貨地若要「有代收 / 無代收」等多組設定，需自行切分號段（例：2000 張平分各 1000） | 鼎新 A1 |
| 號碼不足 | 取號前檢查剩餘量，不足要先向大榮申請新號段再列印 | 鼎新 A1 |
| 刪單 | 已上傳的單號刪除重做會**遺失該號**（下次取下一號，不回收） | 鼎新 A1 |
| 重送 | 上傳失敗修正後重送，沿用原 `BLN`（未刪除時） | 鼎新 A1 |
| 測試 / 正式分開 | 帳號表的常溫區間分「正式」「測試」兩欄 → 號段分環境存 | 官方規格 |

**第三方配號實作（matrix-platform，常溫）**：`BLN = intval(號段起始前綴) + DB sequence.next()`，以數字相加產生（2023-10 從「前綴字串 + 4 位補零序號」改成「數字相加」）。低溫要先遞增 9 碼流水號再補檢查碼（見 `code-examples.md` §4 / `php-client.md` §2）。實作時務必：

- 用 DB sequence / 交易鎖確保**同號不會被兩筆訂單拿到**；
- 取號後若建單失敗，**沿用同號重送**，不要再取新號（避免號段浪費與號碼遺失）；
- 記錄「已用 / 剩餘」，剩餘低於門檻時告警。

**建議資料模型（非官方）**：`kerrytj_bln_ranges(id, env, customer_no, is_cold, start_no, end_no, next_no, station, created_at)`（低溫存前 9 碼流水號）+ 每筆出貨記錄 `bln`、`kerrytj_result`、`area_data`、`raw_response`。

## 4. 業務規則（官網 FAQ / 託運條款）

以下皆為**官方營運規則**（`https://www.kerrytj.com/zh/faq`、`https://www.kerrytj.com/zh/order` 託運條款），可作為 API 欄位驗證的業務依據。

### 4.1 代收貨款（COD）

- **僅限契約客戶**；每筆代收上限 **NT$50,000**（= `AC` Range 0–50000）。
- 費用：銀行匯款費每次 30 元；服務手續費 = 代收金額 × 1%，最低 30 元。
- 匯款時效依合約：月匯（每月 26 日）/ 週匯（每週三）/ 一週二匯（週三、五）/ 日匯；遇國定假日順延。
- 代收明細每週以 e-mail 寄送。

### 4.2 報值（貴重品）

- 報值費 = 報值額 × 1%；報值額每筆上限 **NT$50,000**（= `DeclaredValue` Range 0–50000）。
- 未報值：每公斤最高 200 元或每件最高 3,000 元為賠償上限；報值件以報值額賠償（上限 5 萬）。有合約依合約。
- 貴重品專人交接、與一般品分流作業。

### 4.3 尺寸 / 重量 / 才積

- 單件建議 ≤ 30 kg、長寬高單邊 ≤ 45 cm、單件 ≤ 7 才（一人可搬動為原則）。
- 才積 = 最長 × 最寬 × 最高（cm）/ 27000；1 才 = 1 立方台尺 ≈ (30 cm)³；**1 才 = 10 kg**；重量與才積取大者計價。
- 超長（高或長 > 160 cm）、超重（> 40 kg）、超大（> 7 才）運費加 5 成；裸裝 / 過長 / 不規則改以棧板計價（標準棧板 100 × 110 cm，堆高 ≤ 160 cm）。

### 4.4 運費結構與付款

- 運費 = 接費 + 本運費 + 送費（區內 / 區外）+ 特殊服務費 + 聯運費；同筆低於底價以底價計；運費一律含稅。
- 付款方式：**現付**（寄件人交件時付）、**到付**（收件人付；寄收任一方須為契約客戶）、**月結**（契約客戶）。
- 特服費區域：加工區、碼頭、貨櫃場、賣場 / 統倉、公家機關 / 學校 / 醫院 / 百貨 / 世貿等同址多單位、工業區 / 科技園區。
- 聯運費：偏遠鄉鎮或離島轉由聯運行 / 海空運公司聯合運輸時加收。

### 4.5 溫層

- 低溫配送：冷藏 0~10°C、冷凍 -12°C 以下（官網配送頁）；倉儲 -25°C ~ 7°C。
- 低溫件需預冷：冷藏 6 小時、冷凍 12 小時以上；依溫層分開交寄；低溫貨件收件後 1 小時內須反映並拍照。
- 一般「線上託運」（散客）的禁運清單含「冷凍、冷藏或其他需溫控運送之貨物」——低溫需走低溫車隊 / 契約。

### 4.6 配送時效與作業時間

- **自 107/1/1 起停止假日（週六、日）配送。**
- 線上託運登錄時間（散客）：平日 16:00 止、週六 14:00 止（自 106/06/26 起）。
- 配送兩次仍無法收件，改請收件人至站所自領。
- 收件人發現內部瑕疵須於收件後 3 日內通知（低溫 1 小時內）。

### 4.7 地址 / 收件限制

- 不收郵政信箱。
- 「XX 所站止」= 到營業所自領；集貨站只收貨不提供自領，自領貨件須寄到營業所。
- 寄出後改址：由寄件人聯絡寄貨站所；未配達且跨縣市 / 不同站所加收差價，已配達重新計價。

### 4.8 禁運品（託運條款摘要）

槍炮彈藥刀劍、走私違禁品；現金票據有價證券；珠寶古董藝術品貴金屬；信用卡提款卡；遺骨牌位佛像；活體動物、動物屍體、易腐敗物（含母乳、疫苗）；證件類；無法複製的圖稿磁碟；石材玻璃易碎品；冷凍冷藏需溫控貨物（散客）；煙火油品瓦斯高壓瓶化學品；違反公序良俗物品。

## 6. 待向嘉里大榮索取清單

### 6.1 仍待索取 / 確認（向業務或資訊窗口照此清單問）

1. **帳號表填值**：規格書 v1.1.0 第 2 頁「API 帳號詳細資訊」**正式 / 測試**兩欄（客編、帳號、密碼、常溫區間起迄）——目前拿到的是空白模板。
2. **低溫號段**：帳號表只有常溫區間；若要寄冷藏 / 冷凍，需申請 10 碼低溫號段（測試 / 正式各一）。
3. **測試環境行為**：`EDIEntranceTest` 建的單會不會派車、能不能在 `KerryTracingEDI` 查到貨況、測試號段可否重複使用。
4. **錯誤訊息表**：`Data[].Error` 完整清單；`Result 03` 為何不回原因。
5. **字元計算**：`Consignee` / `Shipper` STRING(6) 是以「字元」還是「byte」計；超長時回什麼錯誤（是否自動截斷）。
6. **`Count` 語意**：成功筆數或處理筆數（範例推得為成功筆數）。
7. **`CON` 在 Report 是否必填**：欄位表非必填，但錯誤範例出現「出貨單號必填」。
8. **`PickupV2` 方向**：官方欄位名 `Shipper` = 取件人、`Consignee` = 收貨人；確認退貨情境「消費者 = Shipper、商家 = Consignee」。
9. **取消託運單**：規格書無取消 API；未交寄單如何作廢、號碼是否回收。
10. **貨況查詢**：批次上限、限流、可查期限；「回傳貨況預設為當天貨況」的實際語意；是否有 webhook / FTP 主動推播。
11. **標籤**：`GetLabelPdf` 尺寸；是否允許自繪標籤及條碼規格。
