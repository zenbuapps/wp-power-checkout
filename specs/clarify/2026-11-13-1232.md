## AI 自行決策（附 trade-off，未丟回用戶）

- D1 領域歸屬：新建 `Domains/Checkout/`（結帳體驗強化），四功能各一個 Service；設定以虛擬 provider id `checkout_enhancement` 存 `woocommerce_checkout_enhancement_settings`，重用既有 `GET/POST /settings/{provider_id}`，不新增 REST 端點。trade-off：不進 `GET /settings` 列表（SPA 直接打單一端點），換得零後端 API 改動。
- D2 每個子功能獨立開關（姓在前、台灣地址、手機檢查、虛擬隱藏地址、虛擬自動完成、免運提示 = 6 個 toggle）。
- D3 姓在前名在後只對 country=TW 生效，以 `woocommerce_get_country_locale` 的 TW locale 調 priority → 傳統＋區塊結帳都吃得到。trade-off：與 woomp 全域對調不同；外國地址維持 WC 原排序。
- D4 「虛擬商品」= 購物車/訂單內「所有」品項 `is_virtual()`；混合購物車一律視為實體。可下載但非虛擬 = 實體。
- D5 虛擬商品隱藏地址：隱藏並取消必填 billing address_1/address_2/city/state/postcode/country；保留姓名、電話、Email、公司。country 被隱藏時以商店基本國家作為 TW 判定依據。傳統結帳用 `woocommerce_checkout_fields`；區塊結帳以頁面載入時的購物車判定，透過 locale `hidden`+`required=false` 實作。trade-off：區塊結帳在結帳頁內移除實體商品後，欄位不會即時隱藏（仍可送出，只是多顯示）。
- D6 手機檢查只在 TW 地址時生效；驗證前先去除空白與連字號，不改寫顧客輸入值；billing_phone 與 shipping_phone（有值時）都檢查；傳統用 `woocommerce_after_checkout_validation`，區塊用 Store API 結帳驗證（伺服器端擋下）。不納入 woomp 的「姓名至少 2 字」（用戶未要求）。
- D7 與 woomp 並存：PC 開關預設不偵測 woomp；設定頁顯示提示「若 woomp 同名功能已開啟請擇一」。（並存站 demo 已存在）
- D8 免運提示樣式：提供背景色/文字色兩個設定，預設沿用 woomp `#d36f6f` / `#ffffff`。
- D9 免運差額計算沿用 WC 內建免運方式語意：顯示小計（含稅與否依商店設定）− 折扣（`ignore_discounts=yes` 時不扣），四捨五入至商店小數位；requires=`both` 時僅在已套用免運優惠券時顯示差額；requires=`coupon` 不顯示；同時有多個門檻取最小正差額。
- D10 自動完成不得造成發票重複開立 → 沿用既有發票 provider 防重複行為（實作期驗證，列入 Execution Plan 風險，不是業務問題）。

## Q&A

- Q1: 「台灣地址格式」範圍？ → A: B — 縣市改下拉（woocommerce_states 提供 TW 22 縣市，傳統＋區塊皆支援）；鄉鎮下拉＋郵遞區號自動帶入僅傳統結帳。既有 TW 顯示格式（DefaultSetting）維持永遠啟用。
- Q2: 手機格式規則？ → A: A — 僅手機，去除空白/連字號後須符合 ^09\d{8}$。
- Q3: 6 個開關升級後預設值？ → A: A — 全部預設 no。
- Q4: 免運門檻來源？ → A: A — 讀 WC 內建「免運費」(free_shipping) 運送方式的 min_amount，依目前運送區域判定。
- Q5: 提示位置與區塊結帳？ → A: C — 購物車頁＋結帳頁運送區上方單一提示列，傳統與區塊結帳皆支援。
- Q6: 文案預設？ → A: yes — 未達「再買 {price} 元即可享免運」／已達「已享免運」。
- Q7: 管理員手動改為處理中也觸發自動完成？ → A: A — 是，任何轉為處理中皆觸發。
